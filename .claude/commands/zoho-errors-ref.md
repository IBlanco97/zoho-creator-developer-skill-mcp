# Zoho Errors & Limitations Reference

Módulo complementario de `zoho-creator-dev`. Tabla de errores comunes con causa raíz y solución.

---

## Errores comunes y soluciones

| Problema | Causa | Solución |
|---------|-------|---------|
| "Number of statement execution limit exceed Line:(N)" en línea trivial | Page script heredado de duplicado consume el límite ANTES del snippet. Línea N es de la función, pero el contador ya llegaba lleno | **Diagnóstico primero**: reemplaza la función con 2 líneas (`convs = Form[ID != 0]; return "count=" + convs.size();`) — si sigue fallando, el problema es el page script, no la función. Fix: Page Builder → "Secuencia de comandos" → borrar script heredado → "Guardar". |
| "Number of statement execution limit" con pocos registros | Loop anidado: `for each tid in lookup_list` dentro de `for each f in Form` hace 1 query por tech por registro. Coste O(N×M) | Eliminar inner loop de lookup. Usar `.count()` para KPIs, no iterar. `max`/`order by` NO válidos en `for each` header — usar `break` con contador |
| `mcp__playwright` o `mcp__plugin_playwright_playwright__*` "Browser is already in use for ...mcp-chrome-{id}" tras un disconnect del server MCP (herramientas desaparecen de golpe) | El proceso `chrome.exe` (con `--remote-debugging-pipe`) queda huérfano vivo aunque el servidor MCP que lo controlaba haya muerto — el perfil sigue "locked" para CUALQUIER servidor (el mismo u otro `plugin_*`) que intente reabrirlo. Cambiar de servidor plugin NO ayuda si apunta al mismo `user-data-dir` | Matar el proceso zombie y reintentar con el mismo o cualquier server: `Get-CimInstance Win32_Process -Filter "Name = 'chrome.exe'" \| Where-Object { $_.CommandLine -like '*mcp-chrome-{id}*' } \| ForEach-Object { Stop-Process -Id $_.ProcessId -Force }` (matar TODOS los procesos con ese `user-data-dir`, no solo el principal — incluye gpu-process, utility, renderer). Esperar ~2s y reintentar `browser_navigate`. Puede repetirse si el crash ocurre de nuevo durante la sesión (visto 2x en la misma sesión tras `browser_evaluate` con payload grande). ⚠️ **Si hay OTRA sesión de Claude Code activa en otro worktree**: el perfil de Chrome (`mcp-chrome-{id}`) es COMPARTIDO entre worktrees del mismo repo — NUNCA matar el proceso sin confirmar con el usuario, mataría el navegador de la otra sesión. En ese caso solo queda esperar/reintentar `browser_navigate` periódicamente (o pedir al usuario que cierre su sesión/navegador) hasta que el perfil quede libre; el servidor MCP puede incluso desconectarse solo (herramientas `mcp__playwright__*` desaparecen) y reconectar más tarde sin intervención — reintentar `ToolSearch` cuando el sistema avise "MCP server reconnected". |
| App IDE árbol: click navega fuera al preview | Clickaste `a.zc-comp-link` en vez del tree item | Usar `a.zc-dem-box-sizing` + scroll 28000 |
| App IDE árbol: `find('Inicio')` no encuentra | Muestra display name, no link name | Buscar por display name visible en IDE |
| Portal no refleja cambios ZML | SPA cachea la página | `location.reload(true)` (hard reload) |
| ZML no guarda con "Apply" | "Apply" es del popup del ícono | Usar `a.zc-dem-savescript` |
| beforeunload dialog al navegar desde IDE | Cambios sin guardar | Portal en tab SEPARADO |
| beforeunload en Page Builder al navegar con `browser_navigate` | `browser_navigate` dispara `beforeunload` nativo del PB; `browser_handle_dialog` no puede pre-registrarse para este caso | En `browser_evaluate`: `window.onbeforeunload = null; location.href = 'target-url';` → esperar dialog con `browser_handle_dialog accept:true` si aparece |
| Editor Deluge en blanco | `zohoedit` timeout | Recargar URL + esperar 20s |
| `invalid_client` OAuth | Credenciales expiradas | Verificar `.env`, regenerar refresh token |
| `browser_snapshot` vacío tras navigate | Carga incompleta | `browser_wait_for` 5-10s adicionales |
| `browser_snapshot` vacío en App IDE | Árbol accesibilidad solo en carga inicial | Usar `browser_evaluate` con `document.querySelectorAll('a.zc-dem-box-sizing')` |
| Eliminar componente via JS no funciona | `event.isTrusted` check | Click real del usuario obligatorio |
| "Listo" falla tras guardar snippet | Panel Configurar sigue activo | Remover clase `zc-pb-popup-show` + `alertMask.display=none` + `builder-close.click()` |
| App IDE botón "Más" no encontrado por textContent | Solo tiene ícono, no texto | Buscar por posición relativa a "Listo" |
| Link name con caracteres especiales | Zoho codifica vocales acentuadas | `list_forms` o buscar en tabla `/workflow/edit` |
| `browser_click` timeout / pointer interceptado | Overlay del form builder | `browser_evaluate` con `.click()` en JS |
| `page.goto()` con hash no navega | SPA ignora hashchange de goto() | `goto()` doble o `location.href = url` via evaluate |
| `location.href = "#Page:..."` en JS de HTML Snippet no navega | Los snippets se renderizan en un iframe; `location.href` cambia la URL del iframe, no de la página padre. El SPA de Zoho solo intercepta `<a href>` clicks y cambios de hash en el frame raíz | Usar `window.top.location.href = url` en cualquier `onclick` JS dentro de HTML Snippets. Los `<a href="#Page:...">` funcionan porque el SPA los intercepta a nivel del frame raíz vía bubbling. |
| Blank snapshot tras Ctrl+S en form builder | Form builder recarga al guardar con teclado | Usar botón "Listo" |
| Radio button no responde a `browser_click` | Label intercepta el click | `document.querySelector('label[for="id"]').click()` |
| Select2 no muestra opciones / frecuencia no cambia | DOM manipulation no dispara modelo interno | Usar jQuery API: `window.jQuery(sel).select2('val', 'VALUE_ID')` luego click en la opción del dropdown; si aparece overlay `.zc-freezer` → `document.querySelector('.zc-freezer').remove()` antes de hacer click |
| KPI Form Data muestra 0 | `"${LoginEmail}"` se sustituye en diseño | Usar `zoho.loginuserid` directamente |
| Reporte embebido "Ningún registro" | Ownership model del portal | Añadir `["viewall"]` en ProfilePermission |
| `querySelector('#id-VIEW')` SyntaxError | IDs con guión no son selectores CSS | `document.getElementById('id-VIEW')` |
| ZML error "Value not facet-valid" | padding shorthand o action inválido | padding: solo 1 valor. action: ver lista válida |
| Click en fila de rol no abre panel permisos | `<tr>` no es clickable, sólo el `<a>` interno | Click en `a.editProfile.zc-edit-permission` (la clase SÍ existe en la nueva UI 2026) |
| Click tab Permisos via evaluate no carga | `isTrusted` check | Usar `browser_click ref=...` (snapshot fresco) |
| `browser_snapshot` permisos excede tokens | ~1200 checkboxes | Usar `browser_evaluate` directamente, NO snapshot |
| `updatePermissionSet` no persiste | Sesión corrupta (timeout largo) | Sesión limpia, repetir flujo completo |
| `browser_wait_for time: 3000` bloquea 50min | `time:` es en SEGUNDOS | Usar 2-15, nunca valores de ms |
| Página nueva no aparece en portal | TAB permission no concedida | Marcar `_TAB` checkbox en editor permisos |
| `fullPage` screenshot no muestra secciones | Iframes lazy de Zoho | `document.body.innerText.includes('Texto')` |
| Tab incorrecto tras `browser_tabs select` | `page` no sigue tab seleccionado | Portal en tab separado desde inicio |
| Page Builder script no guarda con "Listo" | "Listo" no guarda script abierto | Primero "Guardar" del panel, luego "Listo" |
| `cm.setValue()` no dispara guardado | `setValue()` llama `markClean()` | Forzar dirty con `replaceRange` después |
| `CM.setValue()` en Page Builder no persiste al hacer Guardar | El botón Guardar lee su propio estado interno, ignora el CM editado programáticamente — `storeFunction` XHR sigue enviando el código viejo | POST directo a `storeFunction` con: `scripttype=htmlpagemodify`, `htmlviewid`, `parentPageId`, `linkName` (capturados de red), y `text` = nuevo código |
| REST API devuelve 400 "Please enter a valid input for 'accept' header key" | axios envía `Accept: 'application/json, text/plain, */*'` por defecto; Zoho rechaza cualquier valor que no sea exactamente `application/json` | Pasar explícitamente `headers: { Accept: 'application/json' }` en cada llamada o en el cliente axios |
| `browser_evaluate` replace falla: `code.includes(OLD)` devuelve `false` aunque el patrón parece correcto visualmente | El anchor contiene `'` y se construyó con JS single-quoted string: el escaping `\'` puede producir doble-char o comportamiento inesperado al serializar por JSON. Frecuente cuando el Deluge genera HTML con ambos `"` y `'` | Usar **template literal** (backtick) en el `function:` de `browser_evaluate` para strings mixtas: `` `html + "<div class='x'>"` `` — las `'` son literales, las `"` no requieren escaping. Para diagnosticar: `code.indexOf('fragmento_unico_ascii')` + `JSON.stringify(code.substring(N,N+200))` para ver los chars exactos. |
| Anchor de insert falla (`includes()` false) cuando el nivel de indentación difiere del asumido | Secciones del Deluge tienen distinto nesting. Ej en `DevolverHTMLCalendario52Semanas`: bloque asignaciones (dentro de `for each r` dentro de `for each nameId`) → 4 tabs; bloque permisos (`for each sol`) → 3 tabs. El draft local puede no reflejar esto | SIEMPRE leer `cm.getValue()` e inspeccionar tabs reales: `code.indexOf('solLabel')` → `code.substring(idx-10, idx+80)` para contar. Alternativo: leer desde la función directa via Opción A/B antes de construir el anchor. |
| Workflow "Carga del formulario" (On Load): `input.LookupField` es null aunque URL tenga `?LookupField=ID` | El trigger On Load se ejecuta server-side antes de que la SPA procese los query params — los campos pre-rellenos vía URL no están en `input` en ese momento | No usar On Load para leer campos poblados por URL. Usar On Submit / On Edit en su lugar |
| Campo Number en subform: API devuelve "has exceeded its maximum digits" para IDs Zoho (19 dígitos) | Tipo `Number` tiene límite de ~15 dígitos; IDs Zoho son bigint de 19 dígitos. Deluge maneja bigint internamente pero REST API valida el tipo | Omitir el campo del payload API. En Deluge puedes asignar IDs directamente; el problema solo ocurre al insertar vía REST |

Alternativo: chequear red, `POST /populateCustomFunction → 200` indica save OK |

SÍ existe sobre listas planas/subform (`list()`, `parentRec.Grid`) | Sobre query usar **`.count()`** (`Form[crit].count() == 0` funciona). Solo si el set es enorme y `.count()`/iterar revienta el statement limit, usar contador `cnt_++` con `break` |
| `Form[crit] limit 1` u `offset by X limit Y` da "Improper Statement" en función custom | `limit N` / `offset by` son sintaxis REST v2.1, NO Deluge de custom function (el error se reporta en el `for each` contenedor) | **Server-side `Form[crit]` YA devuelve TODOS los registros** (NO aplica el tope de 200 del REST) → no hace falta paginar; iterar directo. Si hay que limitar, `for each + break` con contador |
| `while(cond)` da "Improper Statement" (línea del `while`) | Deluge en custom functions NO soporta bucles `while` | Usar lista literal de índices + `break`: `indexes = {0,1,2,...,9}; for each i in indexes { x = base + i; if(x > tope){ break; } ... }` |

Es el patrón ya usado en `CrearAsignacionEnCalendario52Semanas` |

Éxito real trae `{"status":"success","functionDetails":{...}}` | Instalar interceptor de RESPUESTA antes del save y leer el body: `XHR load → responseText`. Buscar `status:"success"`. ## Limitaciones conocidas

- **Código Deluge NO accesible via REST API** — solo lectura/edición a través del IDE (Playwright)
- **Rate limit API**: 50 req/min por IP
- **Cuotas diarias Deluge** (2 independientes): "Webhook calls" (`invokeurl`) + "External Call Statements" (todo externo). Patrón: reemplazar APIs externas por lookup tables hardcodeadas. ⚠️ La cuota REST API (`code:4000`) también se agota si se itera un report grande sin criteria — siempre filtrar antes de paginar.
- **`criteriaString` en embed se combina en AND con filtro nativo** — si el nativo tiene `zoho.loginuserid`, embeds admin devuelven 0 resultados.
- **Ownership model**: por defecto portal users solo ven registros que crearon. `["viewall"]` en ProfilePermission para bypass.
- **`zoho.loginuserid` en `criteriaString`**: NO se evalúa (literal). Usar filtro nativo del reporte.
- **Funciones REST**: deben estar marcadas como REST endpoint. Si `invoke_function` falla, verificar esto.
- **`deluge-drafts/` son referencias históricas**, no deployments pendientes. Verificar estado actual en App IDE.
- **Picklist lookup fields** (`values = Form.ID`) almacenan IDs numéricos internamente. `ifnull(field, "")` falla — usar `ifnull(field, 0)`. Para obtener texto: `f.Campo.ColumnaTexto` (dot notation).
- **`contains` en queries solo funciona para text multi-select**, NO para lookup list fields. Para lookup lists usar: filtro por fecha + nested `for each tid in f.ListField { if(tid == targetId) { ... break; } }`.
- **Hash URL `criteria=` ignorado**: `#Report:Name?criteria=ID==123` abre el reporte sin filtrar. Usar campo directo: `#Report:Name?FieldLinkName=value`.
- **MCP REST `zoho-creator` roto, RECURRENTE (visto 2026-07-29 y de nuevo 2026-08-03)**: `list_forms`/`get_records`/etc. dan `Error: getaddrinfo ENOTFOUND ${zoho_accounts_domain}` — variable de entorno del server MCP sin resolver (placeholder literal en vez de valor real), persiste entre sesiones. Si esto ocurre, no perder tiempo reintentando la misma tool ni una sola vez: ir directo al fallback Playwright (form builder vía `li[elname="fieldLi"]`, workflow list vía `/workflow/edit`) y avisar al usuario para que revise la config del MCP server (`.env`/config del server, no arreglable desde la sesión de Claude Code).
